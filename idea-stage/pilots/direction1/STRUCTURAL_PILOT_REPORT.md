# 方向一：结构性 Pilot 结果

**方向：** 推理树分支的多 GPU 放置与 KV 选择  
**运行日期：** 2026-09-30   
**结果类型：** CPU 离散事件模拟；不是 GPU 推理基准

## 结论

当前模拟没有显示“按剩余子树工作量放置”能稳定胜过 KV 成本路由。20 个固定种子、27 个负载配置下，共有 540 组配对比较；oracle sibling-aware 策略的平均 p95 改善约 **0.02%**，281 组更快、259 组更慢。64 个并发搜索时，平均 p95 比 KV-cost 高约 **0.23%**；在随机分支 workload 中高约 **0.81%**。

模拟确实显示了跨 GPU 分支路由相对整棵树固定在一张卡上的收益，但这个收益由普通 least-loaded / KV-cost 路由也能取得。因此这轮结果削弱了方向一的差异化主张，尚不足以证明实际系统中的收益，也不足以彻底否定它。

## 设置

- 4 个同构 GPU 的离散事件模型；每个 workload 同时到达。
- workload：完整平衡树、总节点数相同但子树不均衡的树、带随机终止/继续/分叉的 mixed 树。
- 并发树数：4、16、64；假设链路带宽：5、20、80 GB/s；每格 20 个固定种子。
- 共比较 5 种策略：local-only、least-loaded、KV-cost、单分支剩余工作量 oracle、同父节点分支联合放置 oracle。
- 总计 2,700 行结果（3 种结构 × 3 个并发量 × 3 档假设带宽 × 20 个种子 × 5 种策略）。同一 seed 的策略共享完全相同的树和节点工作量。
- 指标：每个搜索树的完成时间 p50/p95/p99、KV 传输量、前缀重算 token 数。不同策略处理同一棵树，因此模拟中答案质量被假设相同，没有真实模型准确率测量。

## 主要结果

| 并发搜索数 | local-only p95 (s) | KV-cost p95 (s) | sibling-aware oracle p95 (s) | 相对 KV-cost |
|---:|---:|---:|---:|---:|
| 4 | 32.84 | 28.63 | 28.56 | 改善 0.23% |
| 16 | 130.77 | 112.18 | 112.09 | 改善 0.08% |
| 64 | 471.93 | 448.06 | 449.09 | 变差 0.23% |

在 mixed workload、64 个并发搜索时，sibling-aware oracle 的 p95 比 KV-cost 高 **0.81%**，20 个种子中只有 2 个更快。平衡树、4 个并发时有约 0.28% 改善，但该收益没有随着并发增加而保留。

## 解释与限制

这里的 oracle 直接知道每个节点后续子树的真实工作量，比可部署策略拥有更多信息。尽管如此，它仍未获得稳定的 p95 收益。当前证据支持一个窄结论：在这套简化模型里，基于当前 GPU 队列与 KV 传输/重算成本做逐分支路由，已经捕捉了大部分可见收益；额外使用搜索树剩余工作量没有产生稳定改善。

模拟中的服务时间、KV 大小与传输带宽都是人为设定值：decode 60 token/s、prefill 25k token/s、KV 0.5 MiB/token、链路 5/20/80 GB/s。8 张 H20 虽然空闲可见，但本轮没有加载模型或运行 GPU kernel。模型也没有表示真实 KV 容量/淘汰、链路争用、GPU 间服务差异、在线到达过程或答案质量。

因此不能把模拟秒数解释为 H20 延迟，也不能据此宣称系统收益。最有价值的后续验证是在真实 runtime 上重放实际搜索树轨迹，固定答案质量，测量 p95 solve latency、SLO goodput、重算 token 和传输字节，并与 MemServe 风格队列/KV 成本基线比较。
