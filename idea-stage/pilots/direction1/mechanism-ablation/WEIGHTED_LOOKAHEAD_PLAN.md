# 方向一：折扣后代工作量权重机制筛查

- **冻结时间：** 2026-10-04 12:44（Asia/Shanghai）
- **状态：** 执行前冻结
- **背景：** B2-tree 在复验中未显示稳定延迟收益；两个事后诊断出的 broad 树 ID 1、13 在四次配对中均变慢。它们的路径队列时间升高，但现有记录不能证明路由导致该现象。

## 假设与边界

- **机制假设：** `kv-cost-group-tree` 把预估后代工作量以全权重加入当前组的副本负载目标。若预测后代工作量对实际后续队列的贡献被高估，权重 0.5 可能比权重 1.0 更少过度重排分支，同时保留一部分树结构信号。
- **反证条件：** 权重 0.5 没有改变实际分配，或两个运行块中均未达到下述延迟筛查门槛；此时停止调整当前 lookahead 权重，不扩大 GPU 矩阵。
- **结论范围：** 这是对同一冻结 16-tree trace 的机制筛查，不是独立样本确认、显著性检验、普遍树形结论或 SLO 证据。树 ID 1、13 是根据已完成结果事后选出的诊断线索。

## 冻结配置

- **模型与数据：** DeepSeek-R1-Distill-Llama-70B bf16；同一 GSM8K 16-tree cohort、既有冻结 prompt trace、service-rate profile 与 output-length profile。所有臂使用相同数据、prompt、采样参数、解码上限及缓存清理步骤。
- **设备与并发：** 新一轮使用空闲 H20 GPU 4–7，组成两个 TP=2 vLLM 副本；客户端并发 4，router capacity 2。仅顺序运行一个条件，避免条件间资源竞争。
- **条件：** flat（后代工作权重 0）、现有 B2-tree（权重 1.0）、折扣 lookahead（权重 0.5）。仅 tree policy 接收该权重参数。
- **运行顺序：** 块 A：1.0 → 0.0 → 0.5；块 B：0.5 → 0.0 → 1.0。每次主运行前清空两个副本的 prefix cache。该镜像顺序平衡两端位置；flat 两次都居中，仍存在顺序限制。
- **主指标：** 每轮 16 棵树的 completion latency 中位数。分别在 A、B 块内比较 0.5 与 flat，并报告所有逐树时延。
- **机制诊断：** 每树 worker assignment、完成 token 数、预测缓存前缀、服务端 queue / prefill / decode telemetry，以及 broad 树 ID 1、13 的路径分量。实际队列路径是结果分解，不能单独识别因果机制。
- **质量门：** 每臂必须有 16/16 完整树和完整必需的 request telemetry；任一块中的多数正确树数不得低于 flat。质量门只用于发现明显回退，不代表质量非劣性。

## 决策门槛

- **继续信号：** 权重 0.5 在 A、B 两块内都比 flat 至少快 5%，并通过完整性与质量门；才值得转到新的独立 cohort 复验。
- **停止：** 任一块未达到 5% 筛查门槛、数据不完整、资源预算触顶或服务无法清理时，不再启动本矩阵剩余条件；报告为阴性或不完整筛查，不临时追加重复。
- **GPU 上限：** 新账本总上限 200 GPU-min，其中 20 GPU-min 只用于清理；主运行、启动与预检合计不得超过 180 GPU-min。达到可用预算上限即停止。
