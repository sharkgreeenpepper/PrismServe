# 固定输出长度诊断：结果与分析

- **日期：** 2026-10-01 11:49（Asia/Shanghai）
- **执行代码提交：** `00d9d12` (`feat(pilot): add fixed-output mechanism diagnostic`)
- **目的：** 控制生成 token 数，观察树感知剩余工作量项是否仍改善放置结果。
**结论：** 队列压力下两策略的总体延迟近似持平；树级效果异质，筛查结果为 inconclusive。

## 有效性检查

- 四个主运行各处理相同的 38 个冻结请求；每个请求都恰好返回 256 completion tokens，`finish_reason=length`。每臂总生成量均为 9,728 tokens，prompt 总量均为 17,580 tokens。
- B1 的顺序是 flat→tree，B2 是 tree→flat；每次运行前都重置两副本的 prefix cache。
- 四个主运行的 vLLM 队列阶段观测数均为 38；加权平均 queue wait 为 4.575–4.990 秒，超过 0.1 秒门槛。队列指标仅按整轮/副本汇总，不能分配到单棵树。
- 单树 sanity 也通过 256-token 校验。全部 4 个主运行完成；未运行 local-only/least-loaded 参考臂。账本记录本轮消耗 28.452/35 GPU-min，服务进程已退出，GPU 4–7 已释放。

## 解释范围

1. **不再观察到上一轮约 10.3% 的总体中位数差距。** 这与“生成工作量差异可能解释了上一轮的部分差距”相符，但不是因果证明：本轮同时把执行输出和路由器的预期输出 profile 都改为 256 tokens。
2. **当前 tree 路由没有显示总体延迟优势。** 它使 B1/B2 的路由估计 cached-prefix tokens 从 9,712 降至 8,672/7,968，服务端 queue mean 增加约 0.32–0.41 秒。调度项似乎在当前小样本中改变了负载分布，同时牺牲部分 prefix locality；逐树 queue/prefill/decode 数据不可用，因此不能把局部变化归因给某个具体因素。
3. **不评价答案正确率。** 强制生成 256 token 会截断自然回答，本轮只诊断固定工作量下的调度和延迟。
4. **决策：** 按冻结门槛，本轮 inconclusive；不在同一四棵树上继续堆重复。它既没有支持当前启发式的总体收益，也不足以否定树感知调度。

## 后续建议

若继续方向一，应先选择新的独立推理树/问题 cohort，再运行自然生成端到端对照；固定输出长度只保留为解释生成工作量的辅助诊断。建议保留 flat 与当前 tree 两臂，并在方案中加入能显式约束 prefix-cache 损失的候选策略；运行前冻结样本、顺序、阈值与预算。扩大测试前应保证能记录逐请求等待/放置与服务端阶段数据，且不要用四树最大值声称 p95。
