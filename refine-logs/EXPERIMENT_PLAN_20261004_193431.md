# 方向一：在线展开推理树的跨副本调度实验计划

**状态：** 新颖性查新后重构的计划；尚未实现在线树运行器，GPU 实验未启动。
**日期：** 2026-10-04
**问题：** 当推理树的分支、终止与后续节点在执行中才逐步出现时，预测未展开后代的服务需求，是否能在队列/KV 与已知工作流调度之外，改善整棵树的完成表现？

## 问题与方法主张

近期查新发现，[TOPAS](https://arxiv.org/abs/2608.25523) 已将剩余关键路径进展与下游前缀复用联合打分，[Maestro](https://arxiv.org/abs/2606.12950)/[FATE](https://arxiv.org/abs/2605.07238) 也覆盖了未来工作估计、就绪前沿与资源/局部性调度。因此本实验不再检验“给冻结树加一个权重是否更快”。唯一待验证的差异是：**路由器不预先获得完整树；它只在父节点完成后看到新分支，并据此预测尚未展开的后代工作。**

在线树执行器和路由器之间必须有清晰边界：

- 搜索策略固定：固定 prompt、解码方式、fanout/depth/node 上限、分支评分和终止规则；所有路由臂调用同一前端。
- 父节点完成后才释放其子节点请求；树运行器不得把完整未来拓扑交给调度器。
- 模型输出的终止标记或固定预算触发分支终止/剪枝；gold answer 只用于离线评分，不能影响在线展开、路由、剪枝或停止。
- 路由器在每个决策时刻只能读取当时已释放的节点、前缀缓存状态、各副本队列/服务率，以及从训练/校准集学得的预测器。不能读取未来孩子、未来终止标记或测试答案。
- 每个树事件都记录 parent/node ID、release/deadline、深度、终止/剪枝原因、预测值、路由决策、缓存命中、队列与服务时间，确保能复算决策。

若没有现成搜索前端能提供上述事件接口，先实现最小在线 driver；在此之前禁止用预生成树或冻结 trace 冒充在线拓扑实验。

## Paper Storyline

- **主文必须证明：** 现有队列/KV 或已知工作流调度在在线、未显露拓扑的搜索树上遇到明确失败模式；提出的后代预测补上该缺口，并改善整树尾延迟或 SLO goodput。
- **主文必须隔离：** 搜索策略和质量保持一致；路由器看不到未来树；对比相同队列/KV 信息下的 known-DAG remaining-path scheduler。
- **附录支持：** 预测器校准、服务率漂移、逐树轨迹、tree-shape 分层、调度开销、不同 fanout/depth/到达率。
- **暂不主张：** KV 迁移收益、通用 agent 系统收益、多模型路由、所有树形均改善、仅凭冻结树重放证明在线收益。
- **实验有意删减：** 不继续调 frozen-trace 中的 0.5/1.0 标量权重；不扩展同一 cohort 的更多重复；不将 16 树的 p95 当作稳定论文估计。

## 实验 Blocks

### B0：在线树与调度器接口冻结（0 GPU）

- **Claim tested：** 运行器能保证调度器只见已释放节点，所有树事件与完成指标可复算。
- **Why this block exists：** 这是主新颖性差异的实现条件；如果未来拓扑被预先载入，实验即不检验目标主张。
- **Dataset / split / task：** 由脚本合成的微型 fixture 树；另用历史 trace 只验证兼容性，不作为在线结果。
- **Compared systems：** 不跑模型；离线测试 route API 的可见字段和事件顺序。
- **Metrics：** 父子 release 时序、事件 ID 唯一性、预测器输入来源、answer/未来拓扑字段泄漏检查、树完成与剪枝规则可重放性。
- **Setup details：** 每个 child 只能在 parent completion event 后创建；gold answer 存在独立评分层；测试树拓扑不预先传入调度器。
- **Success criterion：** 对每个路由决策，输入快照可证明只含当时已知信息；从事件账本可重放所有决策；必需 telemetry 完整。
- **Failure interpretation：** 任一未来信息泄漏或事件缺失，禁止启动 GPU；修复后重新冻结接口和哈希。
- **Table / figure target：** 方法图与在线决策字段表。
- **Priority：** MUST-RUN。

### B1：最小在线 live-tree smoke（≤80 GPU-min 预算规划，未启动）

- **Claim tested：** 在线树实际产生可变 fanout、终止/剪枝，且隐藏后代预测会影响跨副本派发。
- **Why this block exists：** 先判定 novelty-critical mechanism 是否真实存在，再决定是否值得跑完整矩阵。
- **Dataset / split / task：** 8 个此前未用过的 GSM8K test 问题；启动前与所有历史索引去重并冻结。
- **Compared systems：** QKV-only 与 proposed unseen-descendant+KV；相同搜索策略与模型配置。
- **Metrics：** 在线展开节点比例、终止/剪枝事件、预测值、路由决定分歧、树完成时间、队列/TTFT/decode、KV prefix hit、生成 token 数、离线 exact match。
- **Setup details：** 沿用已建立的 vLLM 双 TP=2 副本配置，仅在启动前确认模型/runtime/设备状态；temperature=0，固定搜索预算和停止规则；每题单独保存完整节点输出。
- **Success criterion：** 8 题中均能证明 parent-first release、没有未来树泄漏；至少 4 题出现预测项实际改变路由，且日志含相应服务/关键路径数据。此门槛只证明机制可测，不是性能成功。
- **Failure interpretation：** 若树结构几乎固定、预测项不改派发，或路由器需读取预生成拓扑才能改变分配，停止方向一的未知拓扑方法主张；不追加冻结树 GPU 重复。
- **Table / figure target：** 在线拓扑事件示例与派发分歧案例。
- **Priority：** MUST-RUN only after B0 and budget reconciliation.

### B2：强基线下的有限主筛查（B1+B2 合计最多 380 GPU-min 实验预算 + 20 GPU-min 清理预留；当前余额待核对）

- **Claim tested：** 在线后代预测相对强工作流与服务路由基线改善 end-to-end tree p95 / SLO goodput。
- **Why this block exists：** 单独验证 performance claim；B1 的“路由有变化”不能当作收益。
- **Dataset / split / task：** 16 个全新 GSM8K test 问题作筛查，每种 observed tree-shape 分层；分层是运行后描述，不用未来 shape 筛选样本。保留所有失败/未完成问题。
- **Compared systems：** 4 arms，最多 3 baseline families：1) [Preble](https://proceedings.iclr.cc/paper_files/paper/2025/hash/5bc342f48de8264779952fac378f96dc-Abstract-Conference.html)-style queue + prefix-KV locality；2) [TOPAS](https://arxiv.org/abs/2608.25523)/[FATE](https://arxiv.org/abs/2605.07238)-style exposed-DAG remaining-path + locality（明确声明为适配版，不声称复现原论文）；3) [Autellix](https://arxiv.org/abs/2502.13965)-style program attained-service；4) proposed unseen-descendant prediction + 相同 queue/KV 信号。所有 arm 使用相同预测校准数据和相同硬件预算。
- **Metrics：** 主指标为逐树 end-to-end completion p95 及正确完成率/SLO goodput；同时报告 p50、每题延迟、准确率、生成 tokens、树节点数、queue/prefill/decode、KV hit/recompute、路由覆盖、调度开销。16 题的 p95 仅作筛查，不能声称稳定尾延迟。
- **Setup details：** 先运行一个 16 题 block；若 proposed 对最强 baseline 的 p95 改善不足 5%、正确树数降低，或队列门不满足，按冻结停止规则不运行反序 block。若通过，运行第二个反序 block。服务启动时间、session、arm 顺序、cache 清理和全部失败都入账。
- **Success criterion：** 两个反序 block 中 proposed 的 p95 至少改善 5%、树级配对 bootstrap 95% 区间排除零、SLO goodput 不下降，且答案质量达到预先冻结的非劣标准。屏幕只决定是否值得确认，不足以单独支持论文级普遍结论。
- **Failure interpretation：** 若只优于 QKV 而不优于 known-DAG/attained-service，未知后代预测的增量 claim 不成立；若结果不稳定或区间跨零，判 inconclusive；不得修改门槛后补跑。
- **Table / figure target：** 主结果表（延迟/质量/goodput）与预测项消融表。
- **Priority：** MUST-RUN after B1 passes; within reconciled existing approval only.

### B3：独立确认与第二种工作流（正向筛查后另行冻结）

- **Claim tested：** 该差异能跨独立输入、运行时间和另一类动态 workflow 重现。
- **Why this block exists：** 排除单一 cohort/搜索实现依赖，支撑论文贡献。
- **Dataset / split / task：** 完全独立的数学推理问题；再选一种结构不同、可自动验证的工具/多阶段工作流。不可将 GSM8K 单一设置泛化为通用 LLM agent serving。
- **Compared systems：** B2 的四臂；若某基线无法在同等信号下实现，须披露并由独立 reviewer 确定替代。
- **Metrics：** p95/JCT、SLO goodput、正确率/成功率、KV 与队列开销、预测校准和调度 overhead。
- **Setup details：** 根据 B2 盲化先导方差做正式样本量/功效计算；独立 seeds/cohorts、至少 3 个反序运行块；质量非劣界值在看结果前冻结。
- **Success criterion：** 主 claim 在独立 cohort 重现，置信区间支持预设最小效应，正确率通过样本量支持的 non-inferiority test。
- **Failure interpretation：** 如果只在某一种 search policy/workload 成立，缩小 paper claim；若没有独立重现，不能声称通用在线调度效果。
- **Table / figure target：** 独立确认表与跨 workload robustness 图。
- **Priority：** MUST for a paper claim; NOT SCHEDULED until B2 is positive and its power/budget plan is reviewed.

## Compute 与数据预算

- **预算口径：** B1+B2 合计上限为 400 GPU-min，其中最多 380 GPU-min 用于运行，20 GPU-min 留作服务停止/清理。B1 占用最多 80 GPU-min，因此 B2 最多占用剩余 300 GPU-min；如果完整 B2 投影超过 300 GPU-min，则不启动 B2。上一轮实验分别使用了不同 run ledger/approval；本计划不把各账本余额自动相加，也不认为 400 GPU-min 仍全额可用。
- **启动门：** GPU 启动前，先把此前 400/500/200 GPU-min run IDs、实际用量、清理预留和剩余授权合并成一张预算表；若可用授权小于本阶段上限，则先缩小阶段或停止，不能借用别的实验 ledger。
- **B1 投影：** ≤80 GPU-min；实际开销由服务启动、四卡占用与8题长度决定，预算不够时整轮不启动。
- **B2 投影：** 预计 200–300 GPU-min；启动前用 B1 的 walltime/token 分布做逐 arm 最坏情况预算投影，所有 arm 共用一个总账，不拆小任务绕过上限。若不能在 300 GPU-min 内完整跑完冻结样本与必要 block，则不启动 B2。
- **数据：** GSM8K test 的全新索引；与之前所有使用索引去重，记录数据集版本、规范化 trace hash、模型/tokenizer/runtime hashes。用户本地绝对路径只放在未提交配置。
- **人类评测：** 不需要；gold labels 仅用于离线评分。
- **最大瓶颈：** 在线树扩展会增加且改变请求总量；若模型输出驱动分支变化，paired comparison 的有效样本单位是问题/运行块，不是节点。

## 风险与缓解

- **把 frozen trace 误当 live tree：** route API 不接受整张树；每个 child 的 release 必须晚于 parent completion；记录可审计事件账本。
- **比较系统看到的信息不同：** 所有 arm 使用同样已观测节点、服务率、队列与 cache 信息；只改变“是否预测未展开后代”机制；TOPAS/FATE-style baseline 显式标注为 adaptation。
- **输出量与质量混淆：** 固定搜索策略、采样和 node/depth budget；保存完整文本、终止原因和 tokens；gold 只离线评分；不以 16 题相等正确数宣称质量非劣。
- **prediction leakage / 过拟合：** 预测器在不同校准 cohort 冻结；测试任务及未来拓扑不可用于更新；按运行顺序记录 predictor version/hash。
- **尾延迟样本太少：** 16 题 p95 只作筛查；正式 p95/SLO claim 需独立 pilot 方差和功效计算。
- **预算边界不清：** 合并分开的 GPU ledger、预留清理时间、启动前做最坏情况投影；达到门槛立即停，不为了得到正向结果追加预算。
- **改进只是普通 workflow scheduling：** 主比较必须包含 exposed-DAG critical-path + locality；如果 proposed 不优于它，停止“未知 topology”差异化 claim。

## 先运行的三件事

1. **R001（0 GPU）：** 写清在线 tree event/API contract 与可见性规则，检查现有 runner 是否支持；暂不触碰 GPU。
2. **R002（0 GPU）：** 用 fixture tree 走过展开、叶节点终止、预算剪枝和全树结束四种路径，证明日志只在 parent complete 后出现 child。
3. **R003（≤80 GPU-min、门控）：** 用 8 个全新问题跑 QKV 与 proposed 的 live-tree smoke；满足 B1 才进入 B2。
